## 1. 任务背景与核心痛点

当前 Chapter 4 包含高校研究生、软件工程师、文案策划三个角色，但每个角色仅有 3 句简要流程，形式上更像概念演示，未能形成**“身临其境的战术攻防指南”**。

此外，广大的中国政企事业单位行政人员、法务合规人员、人力资源（HR）和国企办公室职员，面临着更为严峻的**保密纪律、公文合规与合规审计压力**，这一高频群体的安全指引在当前版本中仍是空白。

本阶段的目标是：
1. 将既有 3 大剧本全面升级为**“业务痛点 -> 翻车边缘 -> 技能流水线 -> 交付物验证”**的闭环实操；
2. 隆重推出第 4 大角色剧本：**🏢 政企行政与企业知识工作者的一天**。

## 3. 细化工作计划与内容升级设计

在取得 `ref/中国企事业单位AI使用安全纪律与内部红线调研.md` 后，执行 Agent 须落地以下内容：

### 3.1 角色剧本结构标准化升级
每一个角色剧本均按照统一的四段式战术卡片展开：
1. **真实工作痛点与诱惑 (Temptation & Pain Point)**：为什么要用 AI？
2. **高危翻车瞬间 (Near-Miss Incident)**：如果不加防备，差一点引发什么灾难？
3. **自卫技能流水线 (Defensive Pipeline)**：调用哪些具体的 `SKILL.md`？
4. **交付成果与审计留痕 (Verification Proof)**：给领导、导师或客户看的合规产出物是什么样？

### 3.2 现有三大角色剧本深度填充
- **剧本一：高校研究生与学术研究者**：
  - 上午：未发表开题思路沙盒隔离检索 (`scholar-safety`)。
  - 下午：万字综述引文 CrossRef 自动化批量验真 (`bibref-verify`, `the-judge`)。
  - 傍晚：期刊透明度附录与贡献者陈述生成 (`ai-disclosure-convention`)。
- **剧本二：软件工程师与开源维护者**：
  - 上午：生产连接串与私钥本地抹除 (`pii-safe-documents`) + 微虚拟机沙盒执行 (`agent-sandbox-skill`)。
  - 下午：分布式高可用架构红队对抗质证 (`red-team-review`, `sycophancy-challenger`)。
  - 傍晚：Git Pre-commit 密钥拦截 (`repo-security-review`) + SPDX 开源协议合规审计 (`license-compliance-audit`)。
- **剧本三：文案策划与数字营销专员**：
  - 上午：消除 AI 模板机械味润色 (`humanizer`)。
  - 下午：依据中国《广告法》第9条与 FTC 标准逐句排查绝对化用语 (`marketing-claims-review`)。
  - 傍晚：营销落地页 W3C WCAG 2.1 AA 读屏测试与对比度审查 (`web-accessibility`)。

### 3.3 新增第四大角色剧本：🏢 政企行政与企业知识工作者
- **上午 09:30 · 内部涉密会议纪要与公文提炼**：
  - 严禁使用任何带“云端同步”或“AI 听会”的第三方录音转写服务。
  - 纯本地运行 `presidio-anonymize-text` 与 `pii-safe-documents`，将领导姓名、涉密项目代号、未公开财务指标替换为安全占位符后再进行纪要提炼。
- **下午 14:30 · 招标文件审查与商业谈判推演**：
  - 严防直接粘贴含敏感投标报价的完整标书。
  - 调用 `godfly-opposing-counsel` 模拟对立竞争对手与审计官，站在“挑刺找茬”视角逐条扫描我方合同与商务条款中的赔偿陷阱。
- **下班前 17:30 · AI 使用透明度台账与合规留痕**：
  - 依据单位内部保密合规要求，调用 `ai-provenance` 导出完整的提示词输入日志与去标识化记录归档备查，确保在遭遇企业合规内审时能够**一键自证清白**。
