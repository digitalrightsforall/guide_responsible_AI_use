## 1. 任务背景与核心痛点

目前 Chapter 3 的 3.4（智能体执行安全与沙盒）已完成加固，收录了 Dify、FastGPT CVE 与 WorkBuddy 权限分级。然而其余四个板块（3.1 输入脱敏、3.2 事实查证、3.3 破除谄媚、3.5 交付四门禁）目前仍缺少具有穿透力的**真实中国行政执法案例、本土判决文号与底层技术原理解构**。

本阶段将把以下痛点彻底攻克：

3. **决策时不仅是魔鬼代言人**：揭秘 RLHF 奖励机制为何必然诱导大模型谄媚迎合。
4. **交付前四大门禁法制化**：严格对齐《广告法》第9/28条、《无障碍环境建设法》、SPDX 开源协议传染以及杭州互联网法院奥特曼 LoRA 版权案。

## 3. 细化工作计划与内容升级设计

在取得 `ref/中国个人AI安全进阶实证调研_广告版权与注入.md` 后，执行 Agent 须落地以下内容：

### 3.1 Section 3.1（输入前）：准标识符与隐形载体剖析
- **引入马赛克理论 (Mosaic Theory)**：证明单纯隐去姓名无效，说明组合属性（年龄+科室+城市）重组出身份的风险。
- **拆解间接注入三大载体**：
  1. 白底白字 / CSS 隐藏层
  2. 零宽字符（Zero-Width Unicode）
  3. PDF 批注系统覆盖指令
- **联动技能**：`pii-safe-documents`, `presidio-anonymize-text`, `skillguard`, `skill-sentinel`。

### 3.2 Section 3.2（对话中查证）：撕开幻觉伪装
- **概率自回归原理解析**：向读者讲透“下一个词预测”为何天生追求顺畅而非真实。
- **国内严肃学术与司法核验链**：
  - CrossRef / PubMed 官方 API 校验真实文献。
  - 知网 (CNKI) 与中国裁判文书网二次验证要求。
- **联动技能**：`bibref-verify`, `citation-verifier`, `the-judge`, `claim-source-fact-checker`。

### 3.3 Section 3.3（破除谄媚）：RLHF 机制与三级对抗
- **RLHF 谄媚原罪**：引用 Anthropic 2023 报告证实大模型为迎合人类好评，在 >60% 情况下放弃客观事实。
- **三级对抗审阅实操**：微提醒 (`discernment-nudge`) -> 魔鬼代言人 (`devils-advocate-mad-skills`) -> 陪审团 (`the-jury`)。

### 3.4 Section 3.5（交付前四大法定门禁）：法理全闭环
- **门禁一（营销主张）**：对齐《广告法》第9/28条与 FTC 监管；技能 `marketing-claims-review`。
- **门禁二（无障碍）**：对齐《无障碍环境建设法》与 W3C WCAG 2.1 AA；技能 `web-accessibility`。
- **门禁三（凭证扫描）**：对齐 Gitleaks 与 OWASP 密钥防线；技能 `repo-security-review`。
- **门禁四（开源协议与版权）**：对齐杭州互联网法院 (2024)浙0192民初1587号 与 SPDX；技能 `license-compliance-audit`。
- **配套门禁（生成标识）**：对齐《深度合成管理规定》第16/17条显著标识；技能 `ai-disclosure-convention`, `visible-ai-disclosure-pr-gate`。
